# 顧客ドット絵実装 引き継ぎ（2026-10-31）

## 現状
- mainのpackage.jsonはv3.2.1。READMEには6人×8表情の既存キャラクターとPWA更新修正が記録されている。
- Workの画面上でスーパーの買い物かごを持った多様な顧客ドット絵が生成されたことは確認できる。ただし画像の元ファイル・個別スプライト・利用条件・ゲーム内組み込みは未確認。
- チャットにあるスクリーンショットはプレビューであり、透過背景の完成素材や個別キャラクターの原本ではない。これを自動切り抜きして完成素材とみなさない。

## 実装工程
1. Workから元画像・個別素材・生成条件をエクスポートして保管する。人物ID、用途、表情、ライセンス確認状況を一覧化する。
2. 主人公・社長・店長・従業員・森さん・悪魔の既存6人を維持。顧客は別カテゴリとして管理し、既存の描画経路を調査してから追加する。
3. 顧客ごとに一意のIDと画像パス、代替表示を定義。スーパーの買い物かご・商品・接客の文脈に合わせる。体格や属性と迷惑行為を結びつけない。
4. 一覧、接客、炎上、会議など実際に登場する画面に適切な顧客を割り当てる。ランダム表示は既存のゲーム乱数・セーブ再現性を壊さない方式にする。
5. ドット絵の最近傍拡大、背景透過、モバイル幅320/390/430px、reduced-motion、PWAキャッシュ更新を検証する。
6. npm test、npm run build、Chromium/WebKitブラウザ回帰、30週間完走、旧セーブ復元を実施。表示比較のスクリーンショットを残す。

## 完了条件
- 元画像と権利・使用範囲が確認され、各顧客の個別素材がリポジトリに存在する。
- 実際のゲーム画面で新しい顧客が表示され、既存の6人や財務・保存処理が壊れていない。
- テスト結果と公開環境での確認結果を分けて報告する。

本書は作業引き継ぎであり、画像生成・組み込み・テストの完了を意味しない。元素材が取得できるまで画像の実装完了を宣言しない。

## v3.3.0 実装

上記は引き継ぎ時点の記録。現在は提供された okyakusama_pixel_assets_split.zip の132枚を assets/work-import に取り込んでいる。

- 元のシート配置へ復元後、人物の連結領域を検出して隣の人物の混入を解消。白い服や白目の閉領域を残して背景を透過し、余白を調整。減色とPNG最適化により全素材を約3.2MBへ縮小。
- 一般顧客40枠、常連4組×4表情、会話用4人×8表情、アイコン32点、場面12点。
- 会話用の対応は社長、従業員、森さん、悪魔。主人公と店長の新しい独立表情素材は含まれていないため既存素材を継続使用。主要6人の全身表示は既存素材を使用する。
- 顧客は保存済みの初期シードと週から選び、常連の表情は満足度・不満・炎上に連動。外見による事故確率の変更はない。
- 営業、世論、事故対応、作戦選択、経営会議、週次決算、資金ショート、契約終了へ接続。新規PNGの読み込みエラー時は既存SVGへ切り替える。
- 元ZIPの再取り込み先は work-art-staging。加工済み素材の上書きを避け、PNGシグネチャ判定の誤ったエスケープを修正した。
- 自動テスト25件成功。全8エンディング、旧セーブ互換、財務・乱数の回帰を含む。Chromiumの6幅で1359画面と30週完走・オフライン動作を確認。最新版の320px追加検証226画面も成功。
