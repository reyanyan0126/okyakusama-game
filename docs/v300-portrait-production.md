- 新規高精細原画25点の正式採用は **0/25**。
- 現在のレビューUI (`art-review-v280.html`) は**開発ブランチのみ**、PR #31 はドラフト。

## 1. 最初に作る原画
- **主人公 `you-normal.png` 1枚**。既存の主人公の短髪・濃紺スーツ・赤系ネクタイ・落ち着いた表情を保つ。
- 元SVGをそのまま高解像度化しただけ、別業態のカフェ店員、文字入り進捗資料、集合絵、人物切り抜き汚れは不採用。
- 画角は胸上～腰、4:5縦構図、最低1024×1280、透明背景、6MiB以下。人物だけを画面に配置し、背景・文字・枠・ロゴを混ぜない。
- 5表情（normal/happy/angry/sad/panic）は髪・顔・服の設計を共通化。ポーズや目線は表情が読める範囲で変化させる。

## 2. 安全な審査引継ぎ
1. 生成画像は承認前には `assets/approved-cast-v270/` に置かない。候補作業フォルダ（例：`art-candidates/`）に分離。
2. レビュー画面でPNG/WebP候補を読み込み、寸法・比率・透明ピクセルを検証する。
3. 6項目の目視チェックを済ませ、**SHA-256付き審査提案JSON**を出力する。
4. 画像とJSONを同じ内容で保管し、次のコマンドで整合性を検査する。

```bash
node scripts/verify-art-review-v300.cjs art-review-proposal-v280.json art-candidates/
```

5. 結果 `matching` は「画像のバイト列がレビュー時と一致した件数」。**品質承認件数ではない**。
6. 正式採用には別途人間の目視審査と `art-manifest.json` の個別承認が必要。25枚すべてと6項目の最終確認が揃わない限り `status: ready` は不可。
7. 採用後にのみゲームの人物参照を段階的に差し替え、Node/Chromium/WebKit・320/390/430px・セーブ互換を確認してから本番統合。

## 3. 不採用例と再制作基準
- **インフォグラフィック/資料画像**：ゲーム人物単体の原画ではないので不採用。
- **服・顔が別人**：既存人物または同人物の別表情と一致しないので不採用。
- **四角い背景が残る**：ファイルがRGBAでも可視背景があるなら不採用。
- **解像度・容量・比率が規格外**：機械検査で不採用。
- **審査後に画像を加工**：SHA-256不一致で再審査。
- **目視済みと思われるだけの審査JSON**：最終公開の根拠にならない。

## 4. 本番影響
この工程の追加スクリプト・レビュー機能はゲームの経営計算、乱数、30週進行、セーブ、既存結果3コマ漫画を変更しない。本番v2.9.0は据え置き。
